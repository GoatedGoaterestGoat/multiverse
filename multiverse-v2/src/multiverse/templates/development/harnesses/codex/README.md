# Codex

The adapter is JSON plus a short startup instruction. CLI flags were checked against Codex 0.154.0 and the [official reference](https://developers.openai.com/codex/cli/reference/). It uses the installed CLI, account, model defaults, permissions and project context. No hooks or MCP server are installed. The universe bootstrap is passed through `developer_instructions`; this session-specific value overrides a configured value of that key, so put any shared instructions you also need in the universe bootstrap or project AGENTS.md.

Codex chooses its session UUID. The startup instruction asks the model to run `"$MV2_CLI" session-bind --session-id "$CODEX_THREAD_ID"` from its shell tool before working. This records `native_session_id` in the agent's properties. An inherited parent thread ID is removed before launching. Resume uses only that recorded UUID, never `--last` or a name search. If startup was interrupted before registration, bind the exact UUID shown by Codex's `/status` or exit message with `mv2 session-bind --agent AGENT --session-id UUID`. Registration is prompt-driven, not a guaranteed lifecycle callback.

Messages remain in the durable inbox until the model checks `mv2 inbox` and acknowledges the returned cursor. An idle model is not automatically awakened. Attach to ask it to check if needed. Terminal liveness is observed; activity stays `unknown` without an explicit report. Native `/multiverse` slash commands are not registered: send `Please run /multiverse list` as ordinary text, or use `mv2 catalog` from a shell.

For startup problems, use `mv2 inspect AGENT`, inspect `runtime.json`, and check `codex --help`. Authentication, workspace trust and permission prompts remain native and may require attaching. Launch/resume argv and identity are integration-tested with a fake executable; authenticated model turns are not part of the offline test suite.
