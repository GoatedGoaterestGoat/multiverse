# Codex

This JSON configuration references the source-owned Codex adapter package. CLI flags were checked against Codex 0.155.0 and the [official reference](https://developers.openai.com/codex/cli/reference/). It uses the installed CLI, account, model defaults, permissions and project context. No hooks or MCP server are installed. The universe bootstrap is passed through `developer_instructions`; this session-specific value overrides a configured value of that key, so put any shared instructions you also need in the universe bootstrap or project AGENTS.md.

Codex chooses its session UUID. The startup instruction asks the model to run `"$MV2_CLI" session-bind --session-id "$CODEX_THREAD_ID"` from its shell tool before working. This records `native_session_id` in the agent's properties. An inherited parent thread ID is removed before launching. Resume uses only that recorded UUID, never `--last` or a name search. If startup was interrupted before registration, bind the exact UUID shown by Codex's `/status` or exit message with `mv2 session-bind --agent AGENT --session-id UUID`. Registration is prompt-driven, not a guaranteed lifecycle callback.

Messages remain in the core inbox with delivery tracking and explicit acknowledgement. Manual inbox reads use cursor acknowledgement; native-delivered messages use `mv2 ack --message-id ID`. In plain compatibility mode an idle model is not automatically awakened. With schema-2 `settings.inbox_bridge: true`, spawn/resume asks `codex app-server daemon start` to start or reuse the shared daemon for your OS user and `CODEX_HOME`, then connects the native TUI. Multiple agents/projects/monitors share that daemon. Closing Multiverse does not stop it. A managed standalone Codex installation and matching CLI/daemon versions are required; Multiverse never installs, updates, restarts or stops the daemon. `mv2 send AGENT --text TEXT --delivery steer|follow-up` supports native safe-boundary steering and after-turn follow-up, including idle wake. Acceptance does not acknowledge the inbox or confirm an answer. Use `mv2 capabilities --agent AGENT --probe` to check the current exact session. Initial permission flags belong in `spawn_args`: native remote resume inherits saved permissions and rejects explicit overrides. The adapter never removes user-supplied flags or changes native configuration. Terminal liveness is observed. In bridge mode, after the exact session ID is bound, the launch runner watches app-server status: active work is `working`, approval or user-input waits are `waiting`, and idle is `idle`. Other native states, a missing binding, or a disconnected daemon give `unknown`; plain mode stays `unknown`. Status is detected automatically, never set by agents. The watcher filters events by the bound thread ID and closes with the launch; it never resumes a thread or answers a prompt. Native `/multiverse` slash commands are not registered: send `Please run /multiverse list` as ordinary text, or use `mv2 catalog` from a shell.

For startup problems, use `mv2 inspect AGENT`, inspect `runtime.json`, and check `codex --help`. Authentication, workspace trust and permission prompts remain native and may require attaching. Launch/resume identity, busy timing and idle wake are tested with an installed native TUI and local scripted provider. Authenticated model turns are not part of the offline suite. Native service failures are logged in the launch directory.

Explicit `mv2 stop AGENT` cancels that exact native thread's queued work, active turn and background terminals before closing its terminal. It requires a bound native ID and a reachable server. The shared daemon and sibling threads remain running. Confirmed cancelled messages stay in the inbox history and are not automatically retried. Merely disconnecting a native terminal can leave work running.

Plain launches pass the bootstrap with `-c developer_instructions=...`. Codex may warn that command-line configuration overrides require embedded mode rather than its default shared background server. Explicit bridge mode connects with `--remote unix://...`; existing universes are not automatically switched to it.
