# Codex

This JSON configuration references the source-owned Codex adapter package. CLI flags were checked against Codex 0.159.2 and the [official reference](https://developers.openai.com/codex/cli/reference/). It uses the installed CLI, account, model defaults, permissions and project context. No hooks or MCP server are installed. Plain mode passes the universe bootstrap through `developer_instructions`. Bridge mode adds it to the native thread request through a launch-local relay, preserving any instructions already in that request. No native configuration files are rewritten.

On spawn and resume, bridge mode names the native thread after the mv2 agent with `thread/name/set`, after validating and binding its exact ID/workspace. This includes an empty new thread and reapplies the mv2 name on resume. The control request has a three-second bound; a failure is recorded in `runtime.json` while the terminal stays usable. The `session_name` capability reports this support. Plain Codex has no CLI name flag and reports naming unavailable. Naming was exercised with Codex 0.159.3.

Codex chooses its session UUID. In bridge mode, core records the exact thread ID and workspace from the native launch reply automatically, as soon as the TUI creates or resumes its thread. In plain mode, the startup instruction asks the model to run `"$MV2_CLI" session-bind --session-id "$CODEX_THREAD_ID"` from its shell tool before working. This records `native_session_id` in the agent's properties. An inherited parent thread ID is removed before launching. Resume uses only that recorded UUID, never `--last` or a name search. If startup was interrupted before registration, bind the exact UUID shown by Codex's `/status` or exit message with `mv2 session-bind --agent AGENT --session-id UUID`. Plain-mode registration is prompt-driven, not a guaranteed lifecycle callback.

Messages remain in the core inbox with delivery tracking and explicit acknowledgement. Manual inbox reads use cursor acknowledgement; native-delivered messages use `mv2 ack --message-id ID`. In plain compatibility mode an idle model is not automatically awakened. With schema-2 `settings.inbox_bridge: true`, spawn/resume asks `codex app-server daemon start` to start or reuse the shared daemon for your OS user and `CODEX_HOME`, then connects the native TUI through a private relay in the launch runner. The relay adds bootstrap instructions and writable roots to the native thread request because Codex 0.159.2 drops the former and rejects `--add-dir` in remote TUI mode. Multiple agents/projects/monitors share that daemon. Closing Multiverse does not stop it. Matching CLI/daemon versions are required. Codex manages its daemon package during native startup; Homebrew Codex 0.159.2 is supported. Multiverse never invokes daemon installation, update, restart or stop commands. `mv2 send AGENT --text TEXT --delivery steer|follow-up` supports native safe-boundary steering and after-turn follow-up, including idle wake. Acceptance does not acknowledge the inbox or confirm an answer. Use `mv2 capabilities --agent AGENT --probe` to check the current exact session. Initial permission flags currently belong in `spawn_args`: mv2 preserves saved permissions on bridge resume and rejects explicit permission/profile overrides in `args` or `resume_args`. This is an mv2 restriction, not a limitation of the current app-server schema. Initial writable-directory flags are translated to equivalent native thread settings; permissions are preserved and native configuration files are unchanged. Terminal liveness is observed. In bridge mode, after the exact session ID is bound, the launch runner watches app-server status: active work is `working`, approval or user-input waits are `waiting`, and idle is `idle`. Other native states, a missing binding, or a disconnected daemon give `unknown`; plain mode stays `unknown`. Status is detected automatically, never set by agents. The relay and watcher close with the launch. The watcher filters events by the bound thread ID; it never resumes a thread or answers a prompt. Native `/multiverse` slash commands are not registered: send `Please run /multiverse list` as ordinary text, or use `mv2 catalog` from a shell.

For startup problems, use `mv2 inspect AGENT`, inspect `runtime.json`, and check `codex --help`. Authentication, workspace trust and permission prompts remain native and may require attaching. Launch/resume identity, busy timing and idle wake are tested with an installed native TUI and local scripted provider. Authenticated model turns are not part of the offline suite. Native service failures are logged in the launch directory.

Explicit `mv2 stop AGENT` cancels that exact native thread's queued work, active turn and background terminals before closing its terminal. It requires a bound native ID and a reachable server. The shared daemon and sibling threads remain running. Confirmed cancelled messages stay in the inbox history and are not automatically retried. Merely disconnecting a native terminal can leave work running.

Plain launches pass the bootstrap with `-c developer_instructions=...`. Codex may warn that command-line configuration overrides require embedded mode rather than its default shared background server. Explicit bridge mode connects with `--remote unix://...`; existing universes are not automatically switched to it.

Bridge mode also reports measured context usage from native token notifications. The dashboard shows the latest request's tokens and the model context window; cached tokens are already included. Its percentage matches Codex's native 12,000-token baseline adjustment, so it can differ from the raw tokens/window ratio. The relay accepts observations only for its validated thread and core stores them in the current launch's runtime. Resume can replay the native reading without a model call. Until a reading arrives, usage is N/A; after disconnecting, the last reading keeps its timestamp. Plain mode, cumulative token totals, cost and rate limits remain unavailable. Existing terminals need a relaunch to load a newly installed relay implementation.
