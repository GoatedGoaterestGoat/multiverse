# Codex

This JSON configuration references the source-owned Codex adapter package. CLI flags were checked against Codex 0.154.0 and the [official reference](https://developers.openai.com/codex/cli/reference/). It uses the installed CLI, account, model defaults, permissions and project context. No hooks or MCP server are installed. The universe bootstrap is passed through `developer_instructions`; this session-specific value overrides a configured value of that key, so put any shared instructions you also need in the universe bootstrap or project AGENTS.md.

Codex chooses its session UUID. The startup instruction asks the model to run `"$MV2_CLI" session-bind --session-id "$CODEX_THREAD_ID"` from its shell tool before working. This records `native_session_id` in the agent's properties. An inherited parent thread ID is removed before launching. Resume uses only that recorded UUID, never `--last` or a name search. If startup was interrupted before registration, bind the exact UUID shown by Codex's `/status` or exit message with `mv2 session-bind --agent AGENT --session-id UUID`. Registration is prompt-driven, not a guaranteed lifecycle callback.

Messages remain in the durable inbox until the model checks `mv2 inbox` and acknowledges the returned cursor. In plain compatibility mode an idle model is not automatically awakened. With schema-2 `settings.inbox_bridge: true`, core launches an owned native app-server and connects the native TUI to it. `mv2 deliver AGENT --message-id ID` supports native safe-boundary steering and after-turn follow-up, including idle wake. Acceptance does not acknowledge the inbox or confirm an answer. Use `mv2 capabilities --agent AGENT --probe` to check the current exact session. Initial permission flags belong in `spawn_args`: native remote resume inherits saved permissions and rejects explicit overrides. The adapter never removes user-supplied flags or changes native configuration. Terminal liveness is observed; activity stays `unknown` without an explicit report. Native `/multiverse` slash commands are not registered: send `Please run /multiverse list` as ordinary text, or use `mv2 catalog` from a shell.

For startup problems, use `mv2 inspect AGENT`, inspect `runtime.json`, and check `codex --help`. Authentication, workspace trust and permission prompts remain native and may require attaching. Launch/resume identity, busy timing and idle wake are tested with an installed native TUI and local scripted provider. Authenticated model turns are not part of the offline suite. Native service failures are logged in the launch directory.
