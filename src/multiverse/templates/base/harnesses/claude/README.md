# Claude Code

This JSON configuration references the source-owned Claude adapter package. CLI flags were checked against Claude Code 2.1.231 and the [official reference](https://code.claude.com/docs/en/cli-reference). It launches the installed `claude` CLI with its account, model defaults, permissions and project context, appending the universe bootstrap to its normal system prompt. No plugin, hook or MCP server is required unless `inbox_bridge` is enabled.

The Multiverse agent UUID is assigned as Claude's native session UUID with `--session-id`. Resume uses that exact UUID with `--resume`; it never selects a recent session from a shared workspace. Native sessions must remain on disk for resume to work. The inherited `CLAUDECODE` nesting marker is removed because this is an independent tmux agent.

The model checks and acknowledges its durable inbox at work checkpoints. Without `inbox_bridge`, a message does not automatically wake an idle model; attach to ask it to check if necessary. With `"settings": {"inbox_bridge": true}`, `mv2 send` steers the running session: mid-turn at the next tool result, or typed in as a prompt when idle, through the source-owned `multiverse` mod, which also reports the agent's status as working, waiting (a permission prompt or question) or idle (Claude Code 2.1.285; see `docs/harness-adapters.md` in the Multiverse source). Without the bridge, status stays `unknown` without an explicit report; terminal liveness is still observed through tagged tmux panes. `/multiverse` is a prompt convention, not a registered Claude slash command: send `Please run /multiverse list` as ordinary text, or run `mv2 catalog` in a shell.

Use `mv2 inspect AGENT`, `runtime.json` and `claude --help` when troubleshooting. Attach for native login, workspace trust or permission prompts. Launch/resume argv and identity are integration-tested with a fake executable; authenticated model turns are not part of the offline test suite.
