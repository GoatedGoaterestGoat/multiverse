# Claude Code

This JSON configuration references the source-owned Claude adapter package. CLI flags were checked against Claude Code 2.1.287 and the [official reference](https://code.claude.com/docs/en/cli-reference). It launches the installed `claude` CLI with its account, model defaults, permissions and project context, appending the universe bootstrap to its normal system prompt. No plugin, hook or MCP server is required unless `inbox_bridge` is enabled.

Spawn and resume pass `--name` with the mv2 agent name for Claude's prompt box, `/resume` picker and terminal title. The `session_name` capability reports support with or without the bridge. Native display names are labels; exact resume still uses the saved UUID.

The Multiverse agent UUID is assigned as Claude's native session UUID with `--session-id`. Resume uses that exact UUID with `--resume`; it never selects a recent session from a shared workspace. Claude saves nothing until the first message, so an agent stopped before then has no conversation to resume: it restarts fresh under the same UUID with `--session-id` (the original task is not replayed) and its details say so. Native sessions must remain on disk for resume to work. The inherited `CLAUDECODE` nesting marker is removed because this is an independent tmux agent.

The model checks its durable inbox at work checkpoints. `mv2 inbox` shows unread inbox-only messages and marks them read automatically; `mv2 inbox --all` browses full raw history. Without `inbox_bridge`, a live idle session cannot receive native delivery; attach to ask it to check if necessary. With `"settings": {"inbox_bridge": true}`, `mv2 send` steers the running session mid-turn at the next tool result, or delivers the message as a prompt of its own when the session is idle; `--delivery follow-up` waits for the current turn to end. The source-owned `multiverse` mod shows the model the text alone and writes a receipt for `mv2 deliver AGENT --check`; `mv2 ask` answers a side question from the session's transcript without adding to it, which also reports the agent's status as working, waiting (a permission prompt or question) or idle (Claude Code 2.1.287; see `docs/harness-adapters.md` in the Multiverse source). Without the bridge, status stays `unknown`; terminal liveness is still observed through tagged tmux panes. `/multiverse` is a prompt convention, not a registered Claude slash command: send `Please run /multiverse list` as ordinary text, or run `mv2 catalog` in a shell.

With the bridge, a universe can replace Claude's own `/compact` summary with Multiverse tree compaction: enable it for this harness in the universe's `compaction.json` and restart the agent. Each turn's summary tree is built in the background as the turn ends, and `/compact` installs the turns expanded by the agent's scheduler (`mv2 compaction AGENT`). See `docs/compaction.md` in the Multiverse source.

Use `mv2 inspect AGENT`, `runtime.json` and `claude --help` when troubleshooting. Attach for native login, workspace trust or permission prompts. Launch/resume argv and identity are integration-tested; interactive wake is also tested with a local scripted provider; authenticated model turns are not part of the offline test suite.

Steer/follow-up to a stopped or dormant agent resumes its exact conversation with the framed sender and text as an interactive command-line prompt, using `claude --resume UUID -- PROMPT` (without `--print`). The `wake` capability is supported in plain and bridge modes. No mod/extension delivery is needed for this initial prompt. Process startup is recorded as accepted, with consumption unconfirmed. Additional messages during bridge startup remain pending until registration, then drain in order. A failed startup leaves saved input for explicit retry; accepted or uncertain prompts are never replayed. Live plain sessions still cannot receive native delivery. Inbox-only never wakes. Dashboard `m` uses this same send path.
