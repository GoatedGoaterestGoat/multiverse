# Claude Code

This JSON configuration references the source-owned Claude adapter package. CLI flags were checked against Claude Code 2.1.293 and the [official reference](https://code.claude.com/docs/en/cli-reference). It launches the installed `claude` CLI with its account, model defaults, permissions and project context, appending the universe bootstrap to its normal system prompt. `inbox_bridge` works like Codex's: unset is auto (the Multiverse mod and its peer-inbox bridge are used unless the installed Claude Code is older than 2.1.280; then the launch is plain and `mv2 inspect` shows why), `true` requires the bridge (an error if it cannot be used) and `false` launches plain, loading no mod, plugin or hook.

Spawn and resume pass `--name` with the mv2 agent name for Claude's prompt box, `/resume` picker and terminal title. The `session_name` capability reports support with or without the bridge. Native display names are labels; exact resume still uses the saved UUID.

The Multiverse agent UUID is assigned as Claude's native session UUID with `--session-id`. Resume uses that exact UUID with `--resume`; it never selects a recent session from a shared workspace. Claude saves nothing until the first message, so an agent stopped before then has no conversation to resume: it restarts fresh under the same UUID with `--session-id` (the original task is not replayed) and its details say so. Native sessions must remain on disk for resume to work. The inherited `CLAUDECODE` nesting marker is removed because this is an independent tmux agent.

The model checks its durable inbox at work checkpoints. `mv2 inbox` shows unread inbox-only messages and marks them read automatically; `mv2 inbox --all` browses full raw history. Without the bridge (`"inbox_bridge": false`, or an auto fallback), a live idle session cannot receive native delivery; attach to ask it to check if necessary. With the bridge (auto or `true`), `mv2 send` steers the running session mid-turn at the next tool result, or delivers the message as a prompt of its own when the session is idle; `--delivery follow-up` waits for the current turn to end. The source-owned `multiverse` mod shows the model the text alone and writes a receipt for `mv2 deliver AGENT --check`; `mv2 ask` answers a side question from the session's transcript without adding to it, which also reports the agent's status as working, waiting (a permission prompt or question) or idle (Claude Code 2.1.293; see `docs/harness-adapters.md` in the Multiverse source). Without the bridge, status stays `unknown`; terminal liveness is still observed through tagged tmux panes. The bridge lives inside the Claude process, so there is no separate service: when the process ends the mod ends with it, and `mv2 resume` (or a message to the stopped agent) restarts the same conversation, but nothing reconnects a lost terminal automatically as Codex's shared server can. With the bridge, `/multiverse` is a real Claude command: `/multiverse list` prints the catalog, `/multiverse <name> [args]` runs that command, workflow or skill as your own prompt, `/multiverse send <agent> <text>` messages an agent as this agent (to message one as yourself, type to it directly or run `mv2 send`), and `/multiverse inbox` shows this agent's unread inbox-only messages and marks them read. Only a prompt you type runs `send`, `inbox` or a catalog entry. On Claude Code 2.1.292 or newer, typing `/multiverse ` offers the subcommands and catalog entries, and `/multiverse send ` offers this universe's agents. The mod also shows a one-line status line under the prompt (phase, unread inbox count, compaction state), configured by `statusline.json` at the universe root. Without the bridge, `/multiverse` is a prompt convention, not a registered Claude slash command: send `Please run /multiverse list` as ordinary text, or run `mv2 catalog` in a shell.

With the bridge, a universe can replace Claude's own `/compact` summary with Multiverse tree compaction: enable it for this harness in the universe's `compaction.json` and restart the agent. Each turn's summary tree is built in the background as the turn ends, and `/compact` installs the turns expanded by the agent's scheduler (`mv2 compaction AGENT`). Arguments set the scheduler for that compaction only, e.g. `/compact proportional 60k` or `/compact k=4`; free-text instructions are refused. See `docs/compaction.md` in the Multiverse source.

Use `mv2 inspect AGENT`, `runtime.json` and `claude --help` when troubleshooting. Attach for native login, workspace trust or permission prompts. Launch/resume argv and identity are integration-tested; interactive wake is also tested with a local scripted provider; authenticated model turns are not part of the offline test suite.

Steer/follow-up to a stopped or dormant agent resumes its exact conversation with the framed sender and text as an interactive command-line prompt, using `claude --resume UUID -- PROMPT` (without `--print`). The `wake` capability is supported in plain and bridge modes. No mod/extension delivery is needed for this initial prompt. Process startup is recorded as accepted, with consumption unconfirmed. Additional messages during bridge startup remain pending until registration, then drain in order. A failed startup leaves saved input for explicit retry; accepted or uncertain prompts are never replayed. Live plain sessions still cannot receive native delivery. Inbox-only never wakes. Dashboard `m` uses this same send path.
